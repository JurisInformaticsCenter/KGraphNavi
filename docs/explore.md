# 探索グラフと、形・色・大きさの割り当て

種となる語・判例・条などから始めて、関係をクリックでたどりながら目的の判例やその集まりに近づくための画面（`/explore`）と、
ネットワーク図（`show: type: graph`）の見た目の割り当て（形・色・大きさ）について書きます。

- 実装: `kgraphnavi/explore.py`（設定・問い合わせ・画面）、`templates/js/explore.js`（図と操作）、
  `templates/js/encode.js`（形・色・大きさと凡例。ネットワーク図と共通）
- 設定: アプリケーション設定 `explore:`（下記）、ガジェットの `show.encode`・`nodes.<変数>.attrs`・`nodes.<変数>.shape`
- 判例の設定例: `config/caselaw.yaml` の `explore:`、`CitationNetwork`・`RefLawNetwork`

## 1. ねらい

探す人は、はじめから条件を書けるとは限りません。1つの語や判例から、関係する条・論点・判例へ移り、そこでまた次の手がかりを
見つける、という行き来（イチゴ摘み型の探索）をします。これまでの画面でもリソースのページのガジェットから移れましたが、
1ページに1つのリソースしか見えず、どこから来たか・ほかに何があったかが残りませんでした。探索グラフは、次の3つを1つの画面にします。

| | これまで | 探索グラフ |
| --- | --- | --- |
| 次の一手 | ガジェットの一覧を読んで、リンクを選ぶ | ノードをクリックすると、広げられる関係と**件数**が並ぶ（多い・少ないが先に分かる） |
| たどった道 | ブラウザの履歴だけ | 左の欄に手順として残る。手順ごとに加わったノードを強調、1つ戻す、URL で再現・共有 |
| 集まりの形 | 一覧（表） | 形 = 種類、色・大きさ = 選んだ意味で、塊・中心・橋渡し・外れが見える |

## 2. 画面

```text
┌ 左: 種・たどった道・集める ─┬ 中: 図 ─────────────────────┬ 右: ノード ──────────┐
│ [語を入れる][種にする]       │ 色[種類▼] 大きさ[つながり▼]  │ 条 民法709条          │
│ 見つかった種 ☑語 ☑トピック  │ 形: ●判例 ■条 ◆論点 ⬢トピック │ 全体の件数 1,234      │
│ たどった道                   │ 色: ■判例 ■条 …               │ 次に広げられる関係    │
│ 1. パワハラ（語）を種に      │                               │ ● この条を参照する判例 │
│ 2. パワハラ → 判例 30/124件  │       （Cytoscape.js）         │   次の30件（30/1,234）│
│ [1つ戻す][URLをコピー]       │                               │ ◆ 結んだ法的論点   4  │
│ 集める: 図の判例 42件        │                               │ [ページを開く][外す]  │
│ [名前][保存してコレクションで開く]                           │ [これを種に新しく始める]│
└──────────────────────────────┴───────────────────────────────┴───────────────────────┘
```

- **種**: `/explore?q=語` はラベルに語を含むリソースのうち、設定の種類（判例・語・条…）にあたるものを候補にします。
  ラベルが語と同じものを最初の種にし、ほかは左の欄のチェックで加えます。`/explore?uri=<IRI>` はそのリソースを種にします。
- **入口**: リソースのページ（判例・語・条・論点・トピック・分野・人）の見出しの右に「この○○から探索グラフで広げる ›」が出ます。
  押すと、そのリソース1つを種にした図が開き、右の欄に広げられる関係と件数が最初から出ます。
  画面上端の「探索」は、種の無い画面（語を入れて始める）を開きます。
- **広げる**: ノードをクリック → 右の欄の関係を押すと、その先のノードを `limit`（既定 30）件ずつ加えます。
  もう一度押すと次の 30 件。ダブルクリックは、まだ広げていない一番上の関係を広げます。
- **配置**: 新しいノードは親のまわり（図の中心から離れる側）に置き、それまでのノードは動かしません（頭の中の地図を崩さない）。
  「配置し直す」で全体を力学モデルで並べ直します。
- **たどった道**: 手順（種にする・広げる・外す）を残し、URL の `#s=…` に入れます。読み直す・URL を送ると、同じ問い合わせを
  やり直して同じ図を作ります。手順を押すと、その手順で加わったノードを強調します。「1つ戻す」は最後の手順を取り消します。
- **集める**: 図の判例（Shift ＋ドラッグで囲んで選んだときは選んだ判例）に名前を付けて保存し、コレクションの画面で開きます
  （`POST /collections/save_uris`。保存したコレクションの `source` に探索の URL が残るので、どの道から集めたかを後で開けます）。
  2〜4件を選ぶと「並べて比べる」（`/compare`）。

## 3. 形・色・大きさ（見た目の割り当て）

1つの見た目の要素には1つの意味だけを持たせ、意味は画面で切り替えます。

| 要素 | 意味 | 分かること |
| --- | --- | --- |
| 形 | ノードの種類（判例 ●、条 ■、語 ▶、論点 ◆、トピック ⬢、分野、人 ▲） | 次にどの種類の資源へ進めるか |
| 色 | 1つを選ぶ: 種類／たどった順／年／手続・審級・裁判の結果・裁判所（属性） | 偏り（行政訴訟の塊、破棄の多い塊、新しい争点）。たどった順なら、どの手順で何が加わったか |
| 大きさ | 1つを選ぶ: 図の中のつながり／全体の件数（その条・語を持つ判例の数）／同じ大きさ | 中心（多くとつながる）と、まだ広げていない大きな資源 |
| 線 | 実線 = 確かさの高い関係、破線 = 低い関係（論点の候補、トピックの弱、分野のトピックから） | 根拠の弱いつながりを見分ける |
| 線の矢印 | 参照の向き（判例 → 条、判例 → 判例） | 参照する側・される側 |

- 色は値の種類（カテゴリ）なら、色覚の違いに配慮した 8 色（Okabe & Ito をもとにしたもの）を多い順に割り当て、収まらない値は
  「その他」の灰色、値の無いノード（条に「裁判の結果」は無い）は薄い灰色（「値なし」）にします。数（年）なら薄い青から濃い青の濃淡。
- 探索グラフでは、広げてもカテゴリの色は変わりません（一度割り当てた色を覚える）。
- 大きさは面積が値に比例するよう、半径を平方根で目盛ります（民法709条のように飛び抜けた値が、ほかを点にしないように）。
- 凡例の値をクリックすると、その値のノードだけを強調します（もう一度で戻す）。
- 名前（ラベル）は、判例以外、種・広げたノード、図の中で2つ以上とつながる判例と、マウスを乗せた・選んだノードにだけ出します。

### 可視化で見えるようになることの例（パワハラ）

1. `/explore?q=パワーハラスメント` → トピック「パワーハラスメント」→「このトピックの判例」30件（民事訴訟の損害賠償が多い）
2. その中の労災の取消訴訟（行政訴訟）→「判断の中で参照している条」→ 労働基準法79条 →「この条を参照する判例」
3. 色を「手続」、大きさを「全体の件数」にして「配置し直す」と、トピックのまわりの民事の塊と、労基法79条のまわりの
   行政訴訟（労災の不支給の取消し）の塊が分かれ、その間を、両方に入る1件の判例と労災の条（労基法75条・80条など）がつなぐ。
   トピックの一覧（表）では見えなかった「パワハラの労災の行政訴訟」というまとまりと、そこへの入口（条）が見える。

## 4. 設定（`explore:`）

```yaml
- explore:
    title: 探索グラフ
    describe: 語・判例・条などを種に、関係をたどって判例を集めます。
    limit: 30               # 1回に広げる数（最大 200）
    max_nodes: 400          # 図に出すノードの上限
    search_limit: 10        # ?q= で見つける種の数の上限
    save_kind: 判例          # 保存・比べるの対象にする種類
    save_class: caselawo:CaseLawDocument   # 保存するコレクションのクラス
    attrs:                  # 色の切り替えに使う属性（種類の info・関係の問い合わせで ?a_<name> を返すと付く）
      - {name: procedure, label: 手続}
      - {name: result, label: 裁判の結果}
    kinds:                  # ノードの種類。リソースの rdf:type で、上から順に照合する
      - name: 判例
        types: [caselawo:CaseLawDocument]
        shape: ellipse      # ellipse / round-rectangle / diamond / hexagon / triangle / barrel / tag / star / vee …
        color: "#0072B2"    # 色を「種類」にしたときの色（省略時は自動）
        info: |             # 名前・年・属性・全体の件数をまとめて調べる。$nodes は VALUES ?n { … } に置き換わる
          SELECT ?n (SAMPLE(?l) AS ?label) (SAMPLE(?y) AS ?year) (SAMPLE(?r) AS ?a_result) WHERE {
            $nodes
            OPTIONAL { ?n rdfs:label ?l }
            OPTIONAL { ?n caselawp:year ?y }
            …
          } GROUP BY ?n
    relations:              # 広げる関係
      - name: clause_doc    # 英数字（URL の rel= と、手順の記録に使う）
        label: この条を判断の中で参照する判例
        from: 条            # この種類のノードから
        to: 判例            # この種類のノードへ
        direction: in       # 辺の向き: out（$uri → ?n。既定）/ in（?n → $uri）
        directed: true      # false で向きのない辺（類似・上位下位など）
        weak: [中（候補）]  # ?conf がこの値の辺は破線
        query: |            # $uri から ?n を求める。1つの ?n に1行（GROUP BY・SAMPLE）。LIMIT は書かない（画面が送る）
          SELECT DISTINCT ?n ?year WHERE { ?n caselawp:reflawCore $uri . OPTIONAL { ?n caselawp:year ?year } }
          ORDER BY DESC(?year)
```

関係の問い合わせで使う変数:

| 変数 | 内容 |
| --- | --- |
| `?n` | 広げた先のノード（IRI。必須） |
| `?label` `?year` `?count` `?a_<名前>` | ノードの名前・年・全体の件数・属性（種類の `info` でも付く。関係の問い合わせの値が優先） |
| `?conf` | 辺の確かさ・種類（線の上に出る。`weak` の値なら破線） |
| `?weight` | 辺の太さ |
| `?ord` など | 並べ替えに使うだけの変数（`ORDER BY` で使う） |

- 件数は、関係の問い合わせを副問い合わせにした `SELECT (COUNT(DISTINCT ?n) AS ?total) WHERE { { … } }` で数えます。
- 確かさのような文字の値で並べると、文字の順（「中」が「強」より前）になるので、数（`?ord`）で並べてから `IF` で `?conf` にします。

## 5. ネットワーク図（`show: type: graph`）の見た目の割り当て

既存のネットワーク図（参照関係、判例と参照法令の図など）にも、同じ形・色・大きさの切り替えを付けました。

```yaml
show:
  type: graph
  nodes:
    entity:  {label: label, kind: 判例, x: year, shape: ellipse,
              attrs: {procedure: procedure, instance: instance}}   # {名前: SPARQL の変数}
    article: {label: articlelabel, kind: 条, shape: round-rectangle}
  encode:
    color: [kind, procedure, instance, year, component]   # 画面の「色」の選択肢
    size: [degree, pagerank, none]                        # 画面の「大きさ」の選択肢
    labels: {procedure: 手続, instance: 審級}             # 選択肢の名前
    color_default: kind
    size_default: degree
```

- 色の組み込みの選択肢: `kind`（種類。コレクション外は灰色）、`year`（`x` の値）、`component`（連結成分）。ほかは `attrs` の名前
- 大きさの組み込みの選択肢: `indegree` `outdegree` `degree` `strength` `pagerank` `none`。数の属性も使える
- `encode` を省略しても、種類・年・属性・連結成分の色と、つながり・PageRank の大きさを選べます
- SVG での書き出しも形を保ちます

## 6. URL

| URL | 内容 |
| --- | --- |
| `/explore` | 種を入れる画面 |
| `/explore?q=<語>` | ラベルに語を含むリソースを種の候補にする |
| `/explore?uri=<IRI>[&uri=…]` | リソースを種にする |
| `…#s=<手順の JSON>` | 手順（`[["s", 種], ["e", ノード, 関係, offset], ["x", 外したノード]]`）を再現する |
| `/explore/node?uri=<IRI>` | ノードの情報と、関係ごとの件数（JSON） |
| `/explore/expand?uri=<IRI>&rel=<関係>&offset=0&limit=30` | 関係の先のノードと辺（JSON） |

## 7. 気をつけること

- ノードをクリックするたびに、関係ごとの件数を数える問い合わせ（関係の数だけ）を送ります。重い関係（多くの判例が参照する条の
  判例など）は数えるのに時間がかかることがあります。Virtuoso の負荷が気になるときは、設定で関係を絞ってください。
- 手順の再現は、データが更新されると同じ図にならないことがあります（判例が増える・トピックが変わる）。
